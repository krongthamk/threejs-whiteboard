## Thai support after review and features

Open requested scope: support Thai content throughout the same text paths (plain/sticky/shape/import/display names/people/mentions) and canvas/native editing/PNG/SVG/PDF. Translation of application chrome is not specified by the inherited task; root should use the actual user wording when deciding localization scope.

Baseline evidence: `text-layout.ts` ships only Inter, IBM Plex Mono, Noto Sans JP; unsupported glyph widths fall back to one em; renderer has a single globally configured fallback font; CSS/editor and SVG/PDF embed the same three families; font metrics and PDF coverage generators hardcode those families. The sibling research plan in [THAI_SUPPORT_PLAN.md](THAI_SUPPORT_PLAN.md) recommends local licensed Noto Sans Thai, a shared HarfBuzz shaping path, visible glyph outlines in canvas/PNG/SVG/PDF and selectable original Unicode in exports. Preserve Latin/JP layouts. Finding 34/55 and F1/F4 introduce the shared paths to extend.

Required evidence: Thai consonants/vowels/tone marks/dotted marks, spaces and no-space sentences, Thai+Latin+JP mixtures, wrap boundaries, caret/selection/backspace, IME composition, shape vertical alignment, clipboard/reload/convergence, name chips/mentions, PNG1x2x/SVG/PDF glyph/position/ink/text extraction parity; offline local font loading and no missing-font warning for supported Thai.
