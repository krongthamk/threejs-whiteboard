# Deterministic mixed-script text layout

**Evidence retention (October 2026):** Measurements below describe the original historical runs. Generated logs, raw latency/sample files, screenshots, PDFs and auxiliary JSON are no longer tracked. The audit-linked summary JSON and font metrics evidence remain; new run outputs stay local and ignored. Historical measurements were not rerun by this cleanup.

Measured 2026-09-30, using the shipped Inter, IBM Plex Mono and Noto Sans JP WOFF files and pinned `troika-three-text@0.52.5`.

The model now shares the renderer's font resolution rule: once a fallback font covers a glyph, that font continues while it covers following glyphs, including across spaces and newlines. Source text is never Unicode-normalized; UTF-16 source/render caret mappings remain intact. Auto-size, hard wrapping and pure SVG use the same metrics and explicit font runs. For example, 32px Mono `日本語 WWWWWWWWWW` measures **384.128px**, correcting the former **307.2px** result.

`node packages/model/scripts/generate-font-metrics.mjs` regenerates checked-in data, including the source font filenames/SHA-256 hashes and parser version. Noto's 16,732 supported codepoints use sparse GPOS pair candidates and supported GSUB ligatures rather than a 280-million-pair search: 21,803 adjusted pairs and 43 ligatures. Inter/Plex have 170/3 supported combining/ligature sequences. No runtime font parser or canvas measurement enters the model; module initialization only binds imported JSON. Ordinary wrap slices use prefix advances; slices containing ligatures or exceptional glyph positioning are measured separately so a wrap can split a ligature correctly.

The generator records Troika's **raw last-glyph endpoint**, which differs from its font parser's final pen for Japanese punctuation. Noto applies half-width positioning in Troika while native browser text uses full-width punctuation by default. SVG and PDF therefore position affected glyph tokens explicitly, retaining whole-line left/center/right alignment. App export checks coverage and loads fonts without flattening those spans. PDF strict unsupported-codepoint rejection and malformed-font retry remain intact.

## Native editor boundary

The plaintext native DOM editor is intentionally unchanged. The browser may temporarily return to primary Latin and use its native punctuation spacing while committed Troika keeps Noto. This preserves native selection, clipboard and IME behavior. The tests assert text/caret integrity, visible input, and correct committed/reopened auto-size; they **do not assert native editor glyph pixel parity**.

The measured cases cover the shipped Latin/Japanese fonts and listed sequences, not every Unicode shaping combination. A repeated eight-phrase Noto ligature regression exposed 33 output pixels of cumulative PDF width drift. Explicit token positions now remove that drift while retaining exact original text extraction: PDF/SVG ink bounds match and foreground mismatch is 13.50%. jsPDF still renders each token from source cmap glyphs rather than its GSUB ligature, so this is measured tolerance parity, not a claim of identical font shaping. The same new test exposed a separate cold PNG projection issue: shared Troika glyph metadata could become visible before its SDF atlas generation completed in another renderer. The renderer export gate now waits for active shared text syncs; the on-screen/off-screen cold/warm and presence-label regressions pass. Initial failed artifacts remain under `initial-ligatures.*`.
